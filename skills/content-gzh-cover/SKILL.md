# Content 公众号封面

只做一篇文章、一种风格、一张封面。由 `content-gzh-slim` 在保存后调用，使用当前模型判断构图、短标题和 Prompt，不调用旧 V1、Reviewer 或其他 Agent。

## 交互

入口在询问是否需要封面时，一次列出三种文字选项，并根据文章推荐一种、给一句理由：

1. 麦肯锡商业咨询：商业分析、方法论。
2. 实拍写实杂志风：真实场景、实物现场。
3. 复古图纸聚焦风：结构、系统、空间关系。

用户选一种后直接生成。已指定风格不再询问；用户说“你选”“按你推荐”就按文章判断并完成；说不用就结束。不要把推荐当作用户已经同意。不要逐项确认 Prompt、短标题、构图或保存。

## 连续完成

1. 通过 `cover-context --run-id ... --style ...` 取得同一 Run 的已确认正文、当前回读和绑定值（只验证冻结快照与目标文章，不再次检索来源库）；若已有同风格有效封面，复用 PNG，除非用户明确重做。需写回且 `currently_applied` 或记录的 `applied` 为 false 时，用本次绑定值及已有图的 Prompt、标题、生成器和路径调用 save-cover，完成写回或中断记录恢复，不重新生图。读取所选的一份风格参考。从正文提炼核心词与短标题，按该风格选择贴合本篇判断的主体、隐喻或氛围，直接组织提示词。长文章标题不必整句搬上封面；字少允许留白，不为填版增加副标题、标签或无关元素。不改文章标题或事实，用户指定封面原文时逐字保留。
2. 真实加载当前宿主的 `imagegen` Skill，调用实际可用的图片工具生成一张 PNG。目标 2.35:1，背景完全不透明（白底不能用透明替代），中文清楚、主体与题意相关。按下方共用标题规则看横图和实际 1:1 裁切预览，检查文字、风格和裁切，明显错误只修一次；缺工具或仍失败就报告，不用旧图、代码画图或占位图替代。
3. 把实际使用的 Prompt、图片和已取得的绑定值交给 `save-cover`；后台完成保存、必要写回和回读，向用户展示封面与实际保存结果。无需另设 Prompt 文件或人工 Gate。

风格键和参考：
- `consulting`：[麦肯锡商业咨询](references/consulting.md)
- `real-photo`：[实拍写实杂志风](references/real-photo.md)
- `retro-blueprint`：[复古图纸聚焦风](references/retro-blueprint.md)

现有 IP 的明确禁区从本 Run Context 读取；不借用其他账号的身份、事实、行业物件。无 IP 可以正常生成。

## 横图与 1:1 小图共用标题

先按约 2.35:1 的完整横图确定字号、留白及左右图文比例，再检查 1:1 裁切。横图整体好看是构图目标，方形区域是文字完整性约束，不是要求巨字填满的版面。

默认从横图**最左侧**取一个以图片高度 H 为边长的正方形：`[x=0, y=0, width=H, height=H]`。方图背景直接取自同一张横图，铺到四边，不做缩小画面再加垫边或内嵌卡片。若用户指定另一裁切位置，按该位置组织标题，不能沿用左裁结论。

- 全部封面文字（主标题、副标题、必要小字）必须完整落在这个方形内；没有必要的小字就不加。
- 方形占横图总宽约 42.6%；文字四周留正常呼吸边距，约 8%—10% H 可作参考。文字总宽通常不超过横图宽 W 的约 34%—36%，但这只是上限参考，不是必须撑满的目标。
- 字号由横图整体决定。文字较少时保留合理留白，优先自然的两行排版；不要逐行放大到等宽、过度粗黑或为了方图气势牺牲横图比例。
- 长标题先提炼或合理换行，再调整字号；不得截字、横向压扁，或缩到小图看不清。用户锁定文字时不删字。
- 看图时同时检查完整横图及按实际坐标截取的 1:1 预览，必须能读完全部文字。不能只看横图后声称小图通过，也不能另生成一张不同小图冒充裁切证明。
- 安全框只用于内部构图/预览，不画进最终图片；成品不得有 1:1 字样、边框或虚线。

这是后台构图和看图要求，不新增用户确认步骤，也不默认多生一张图片。

## 封面失败清单与反制

组织提示词时逐条自查；命中一条就在提示词里写一句显式反制，不要只在心里规避。

1. PPT / 课程封面感：画面像模板套壳。反制："an editorial magazine cover, NOT a slide template or course thumbnail."
2. 信息图模板感：堆图标、图表、数据、流程。反制："no infographic elements, no charts, no icons, no data labels."
3. 电商广告感：促销感、价格、标语、二维码。反制："no commercial-advertising feel, no price, no slogan, no QR code."

## 后台保存

运行命令使用入口同一包内的 launcher，参数详见入口的 `references/runtime-commands.md`。

`save-cover --run-id ... --candidate ...` 输入 JSON：

```json
{
  "approved_final_digest": "来自 cover-context 的原值",
  "article_digest": "来自 cover-context 的原值",
  "style": "consulting",
  "layout_version": "wide-balanced-square-v2",
  "cover_title": "实际封面文字",
  "prompt": "实际提交给图片工具的完整提示词",
  "image_path": "图片工具返回的实际本地 PNG 路径",
  "generator": "实际图片工具名",
  "visual_checked": true
}
```

`layout_version` 使用 cover-context 返回的原值；旧布局图片不自动复用。只有实际看过横图及同图左侧 1:1 裁切、确认全部标题完整且可读后，才填写 `visual_checked: true`。Host 填写文字无法替代真实工具调用和看图。普通任务没有数组或三风格比较参数。

Obsidian 默认写回；先核对目标库附件规则，必要时提供 `asset_directory`（必须在同一库内）。已有 `A.系统/附件` 时保存到该目录；否则默认同文章目录配图文件夹。仅预览时设置 `apply: false`。原文已被手改、目录越界或现有图片冲突时停止，不覆盖。

飞书来源真实回读后只保存本地封面包，明确报告尚未插入飞书。保存不代表草稿箱或发布。

独立视觉实验可用用户授权的真实文章快照调用本 Skill 的风格与生图能力；不伪造 Run、Gate 或 save 回执。正式 Slim 集成的 `cover-context/save-cover` 必须有有效 Run。开发验收分别调用三次单风格能力，不向日常用户暴露测试分支。
